[textarea Your steps]
Read the ECR, the spec and both SRAM excerpts, and list what's different on the NW61P compared with the NW61F. There are three changes. Write data now arrives one cycle after the command. Read latency is set by the LAT pin. Read data is valid for one cycle only.
Work out the read latency on the boards as they were actually built. The schematic straps LAT low, but ECO-117 in the bring-up log refits every rev C board to LAT high. Even without that, 125 MHz is above the LAT-low limit. So the latency is 3.
Look at step 4 of the bring-up capture. A read issued one or two cycles after a write to the same address returns the old word. Only a read three or more cycles later gets the new one.
Delay the write data by one cycle, so that it reaches the SRAM pins one cycle after its write command.
Lengthen the read pipeline so the returned data is captured three cycles after the SRAM samples the read. Each read's last and error tags need to travel along with it.
Make the output queue deeper and count every read that's in flight. That way stored packets still stream at one beat per cycle, with no gaps.
In both modes, hold back any read of a word written in the last two cycles, so that no read lands in the stale window.
Check the 5-cycle budget for the first cut-through beat. Going through the SRAM now takes at least 8 cycles. To fix this, add a bypass that puts an ingress beat straight into the output queue when nothing earlier is still waiting or in flight.
Keep the bypass consistent with everything else. Advance the read pointer for bypassed words, and don't create a descriptor for a bypassed last beat. SRAM reads must never get ahead of words that aren't yet safe to read.
Extend the retry flush to cover every new read-pipeline stage. Reads still in flight get thrown away, and the packet is read again from its first word.
Write a rev C SRAM model based on the datasheet and the capture. Test it with random traffic, backpressure, retries, dropped packets, mode changes and several DW/AW settings, on both Icarus and Verilator with random power-up.
