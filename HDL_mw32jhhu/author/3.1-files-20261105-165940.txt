// Smoke test for pktbuf on board rev B (NW61F1024 flow-through SRAM).

//

// Sends a few packets in store-and-forward mode, then a few in cut-through

// mode, and checks that they come out unchanged. It is a quick sanity check,

// not a regression: no backpressure, no dropped p ackets, nothing else.

//

// The SRAM model follows docs/NW61F1024_excerpt.m d: command, address and

// write data are sampled at the same rising edge; read data is captured by

// the FPGA at the next rising edge.

module tb_smoke;

localparam DW = 32 ;

localparam AW = 10 ;

reg clk = 1'b0 ;

always # 5 clk = ~clk;

reg rst_n = 1'b0 ;

reg cfg_ct = 1'b0 ;

reg in_valid = 1'b0 ;

reg [ DW- 1 : 0 ] in_data = { DW { 1'b0 } } ;

reg in_last = 1'b0 ;

reg in_err = 1'b0 ;

reg out_ready = 1'b1 ;

reg out_retry = 1'b0 ;

wire in_ready, out_valid, out_last, out_err;

wire [ DW- 1 : 0 ] out_data;

wire [ 15 : 0 ] drop_count;

wire sram_ce_n, sram_we_n;

wire [ AW- 1 : 0 ] sram_addr;

wire [ DW- 1 : 0 ] sram_wdata;

reg [ DW- 1 : 0 ] sram_rdata;

pktbuf # ( .DW ( DW ) , .AW ( AW ) ) dut (

Scripts before and after the model optional, hidden from the model

Run in the box as root, in the workdir: one before the model's first step, one after its last and before the answer file is read. The correct answer and each common mistake run with them too. Use them to set up the starting state, or to pack what the model changed into the answer file, so the model is not graded on packing it. A setup that fails stops the run as an error. A teardown that fails is no answer, a score of 0, as it fails on what the run left; Verify shows it on your correct answer first. What setup makes under the workdir is given to the model's user, so the model can edit it; anything it makes elsewhere stays root's. A teardown that writes the answer file replaces a correct answer typed as that file: write your answers as scripts that change what teardown packs.
